# README intro-first trim rules

README 상단이 길어질 때 무엇을 남기고 무엇을 아래로 내릴지 빠르게 판단하기 위한 기준입니다.

## 유지 / Keep at the top

- 프로젝트 소개 1~3문장
- 대상 사용자
- 즉시 보이는 가치
- 대표 예시 또는 빠른 시작 1세트
- 검증 명령 1개

## 아래로 이관 / Move lower or into docs

- 기여 운영 세부 규칙
- 긴 링크 묶음과 세부 분기
- 반복 설명되는 영어 미러 문장
- 첫 화면에서 바로 필요하지 않은 운영 메모

## 판단 질문 / Decision questions

1. 첫 방문자가 30초 안에 이 저장소의 목적을 이해할 수 있는가?
2. 첫 실행 명령이 상단에서 바로 보이는가?
3. 운영/거버넌스 설명이 프로젝트 소개보다 먼저 나오지 않는가?
4. 같은 메시지를 다른 표현으로 여러 번 반복하고 있지 않은가?

## English mirror

Use this rule card when the README landing section starts to grow too tall. Keep the project intro, audience, immediate value, one featured example/quick start path, and one validation command near the top. Move detailed operations guidance, long link bundles, and repeated English mirror explanations lower or into dedicated docs.
