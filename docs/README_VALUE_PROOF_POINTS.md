# README 가치 증명 포인트 / README value proof points

README 상단에서 프로젝트 소개 다음에 바로 보여줄 **가치 증명 포인트**를 정리한 문서입니다.
이 저장소가 왜 필요한지, 누가 바로 이득을 보는지, 첫 화면에서 어떤 약속을 먼저 보여줘야 하는지 빠르게 맞추는 데 씁니다.

English mirror:
A compact reference for the **value proof points** that should appear near the top of the README right after the project introduction. Use it to keep the landing page focused on why the repo matters, who benefits immediately, and what promise the first screen should make before governance details.

## 한국어 기준 / Korean-first proof points

- **프로젝트 한 줄 가치** — 한국어 기본 흐름으로 스킬을 찾고, 검증하고, PR 증빙까지 이어지는 실행 가능한 큐레이션 저장소임을 먼저 말합니다.
- **대상 사용자 이득** — 탐색형/기여형/운영형 방문자가 첫 화면만 읽어도 다음 문서를 고를 수 있게 합니다.
- **바로 실행 가능한 약속** — 첫 검증 명령, 다음 온보딩 문서, 첫 PR 증빙 경로를 한 번에 보여줍니다.
- **운영 문서는 뒤로** — CONTRIBUTING/정책/운영 기준은 가치 설명 뒤로 내리고, README 첫 화면은 프로젝트 소개 우선 구조를 유지합니다.

## English mirror

- **One-line project value** — say first that this is a runnable curation repo where Korean-first builders can discover skills, validate them, and move into PR evidence.
- **Immediate audience benefit** — help explorer / contributor / operator visitors choose the next doc from the first screen alone.
- **Runnable promise** — surface the first validation command, next onboarding doc, and first PR evidence path together.
- **Governance later** — keep CONTRIBUTING/policy/operations details below the value story so the README remains intro-first.

## 상단 적용 체크 / Landing-page usage check

- README 상단 100줄 안에 이 문서 또는 여기의 핵심 문장이 링크/반영되어 있는가?
- `프로젝트 소개 → 대상 사용자 → 제공 가치 → 대표 예시/빠른 시작` 순서가 깨지지 않는가?
- 운영/정책 링크가 가치 설명보다 먼저 나오지 않는가?

English mirror:
- Does the first 100 lines of the README link to this doc or reuse its proof points?
- Does the order stay `project intro -> audience -> value -> featured examples/quick start`?
- Do governance/policy links stay below the value explanation?
