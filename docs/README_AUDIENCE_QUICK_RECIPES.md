# README 대상별 빠른 적용 레시피 / README audience quick recipes

README 상단을 프로젝트 소개 우선 구조로 유지하면서도, 방문자별 첫 행동을 빠르게 고르게 만드는 짧은 레시피 모음입니다.
English mirror: Short recipes for keeping the README intro-first while still giving each visitor a fast, obvious first action.

## 한국어 기준 / Korean-first recipes

### 탐색형 / Explorer
- 먼저 읽을 블록: `프로젝트 소개 / Project overview` → `프로젝트 한눈에 보기 / Project at a glance`
- 첫 행동: `examples/quickstart.md` 열기
- 확인 질문: "이 저장소가 링크 모음이 아니라 실행 출발점이라는 점이 첫 화면에서 보이는가?"

### 기여형 / Contributor
- 먼저 읽을 블록: `핵심 가치 카드 / Value cards` → `대표 시작 예시 / Featured starter examples`
- 첫 행동: `docs/BILINGUAL_CONTRIBUTION_CHECKLIST.md` → `examples/pr-evidence-mini-walkthrough.md`
- 확인 질문: "첫 PR 증빙 형식과 다음 문서가 스크롤 최소로 보이는가?"

### 운영형 / Operator
- 먼저 읽을 블록: `프로젝트 시작 맵 / Project start map` → `핵심 시작 버튼 / Core start buttons`
- 첫 행동: `docs/README_FIRST_SCREEN_CHECKLIST.md` → `docs/README_AUDIENCE_VALUE_MAP.md`
- 확인 질문: "소개 → 대상 사용자 → 가치 → 예시 → 빠른 시작 순서가 무너지지 않았는가?"

## English mirror

### Explorer
- Read first: `Project overview` -> `Project at a glance`
- First action: open `examples/quickstart.md`
- Check: "Does the first screen make it clear that this repo is an executable starting point, not just a link list?"

### Contributor
- Read first: `Value cards` -> `Featured starter examples`
- First action: `docs/BILINGUAL_CONTRIBUTION_CHECKLIST.md` -> `examples/pr-evidence-mini-walkthrough.md`
- Check: "Can a first PR evidence format and the next doc be found with minimal scrolling?"

### Operator
- Read first: `Project start map` -> `Core start buttons`
- First action: `docs/README_FIRST_SCREEN_CHECKLIST.md` -> `docs/README_AUDIENCE_VALUE_MAP.md`
- Check: "Does the README still preserve overview -> audience -> value -> examples -> quick start order?"
